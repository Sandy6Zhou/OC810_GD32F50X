# mDVR-OC810 单片机视频模块通讯协议

**版本**: V1.0
**日期**: 2026.06.15
**作者**: Harrison Wu (wuyujiao@jimiiot.com)

## 1. 概述

### 1.1 目的

本文档规范 mDVR-OC810 项目单片机终端与视频模块之间的通讯协议，确保数据传输的可靠性、完整性和可维护性。

### 1.2 适用范围

本协议适用于 mDVR-OC810 项目中单片机（GD32F505VGT7）与视频模块（如 dvr 系列）之间的所有串口通讯。

| 参数 | 值 |

## 3. 协议格式

### 3.1 帧结构

本协议参考部标协议（JT/T 808）设计，采用可变长度帧格式：

```
┌─────────┬──────────┬──────────┬──────────┬────────────┬──────────┐
│ 标识位  │ 流水号   │ 命令     │ 数据     │ CRC校验码  │ 标识位   │
│ (1字节) │ (2字节)  │ (2字节)  │ (N字节)  │ (2字节)    │ (1字节)  │
└─────────┴──────────┴──────────┴──────────┴────────────┴──────────┘
```

| 字段 | 长度（字节） | 说明 |
|------|-------------|------|
| 标识位 | 1 | 固定为 `0x7E`，表示帧起始/结束 |
| 流水号 | 2 | 消息发送顺序号，从 0 开始累加 |
| 命令 | 2 | 指令类型标识 |
| 数据 | N | 数据内容，长度 ≤ 1024 字节 |
| CRC校验码 | 2 | 标准 CRC16 校验（CRC-CCITT） |
| 标识位 | 1 | 固定为 `0x7E`，表示帧结束 |

### 3.2 字节序

**总体说明：除特殊说明外，本协议所有多字节字段统一采用大端模式（Big-Endian），高字节在前。**

- **流水号**: 大端模式（Big-Endian），高字节在前
- **命令**: 大端模式（Big-Endian），高字节在前
- **CRC校验码**: 大端模式（Big-Endian），高字节在前

## 4. 转义规则

### 4.1 转义原因

标识位 `0x7E` 用于标识帧的起始和结束。若流水号、模块ID、命令、数据、校验码中出现 `0x7E` 或转义字符 `0x7D`，则必须进行转义处理，避免帧边界混淆。

### 4.2 转义定义

| 原始字节 | 转义后字节序列 |
|---------|---------------|
| `0x7E` | `0x7D 0x02` |
| `0x7D` | `0x7D 0x01` |

### 4.3 转义处理流程

#### 发送消息

```
消息封装 → 计算并填充CRC校验码 → 转义处理 → 发送
```

#### 接收消息

```
接收数据 → 转义还原 → 验证CRC校验码 → 解析消息
```

### 4.4 转义示例

**原始数据**：`0x30 0x7E 0x08 0x7D 0x55`

**转义后**：`0x7E 0x30 0x7D 0x02 0x08 0x7D 0x01 0x55 0x7E`

**详细过程**：
- `0x30` → `0x30`（无需转义）
- `0x7E` → `0x7D 0x02`（转义）
- `0x08` → `0x08`（无需转义）
- `0x7D` → `0x7D 0x01`（转义）
- `0x55` → `0x55`（无需转义）

## 5. CRC 校验

### 5.1 CRC 算法

采用标准 CRC16-CCITT 算法：

- **多项式**: `0x1021`
- **初始值**: `0xFFFF`
- **异或输出**: `0x0000`
- **输入反转**: 否
- **输出反转**: 否

### 5.2 CRC 计算范围

CRC 校验范围：**从流水号开始到数据结束**（不含标识位和 CRC 本身）

```
CRC(流水号 + 命令 + 数据)
```

### 5.3 CRC 计算示例

**输入数据**：`0x00 0x01 0x00 0x01 0x00 0x00`

- 流水号：`0x0001`
- 命令：`0x0001`
- 数据：`0x0000`

**CRC16 计算结果**：`0xXXXX`（需实际计算）

## 6. 命令定义

### 6.1 命令编码规则

命令采用 2 字节编码：
- **高字节**: 功能分类（`0x00` 基础控制，`0x01` 数据查询，`0x02` 配置设置，`0x03` 数据上报）
- **低字节**: 具体指令序号

### 6.2 主动请求与被动响应

本协议支持双向命令通信：

- **DVR → MCU**（视频模块 → 单片机）：DVR 主动发起查询或心跳命令，单片机接收后解析并应答
- **MCU → DVR**（单片机 → 视频模块）：单片机收到 DVR 命令后回复应答，流水号必须与请求一致

**命令编码规则**：
- MCU 侧命令以 `0x2xxx` 开头（单片机发送/应答）
- DVR 侧命令以 `0xAxxx` 开头（DVR 发送，单片机解析）
- 示例：DVR 查询 `0xA003` → MCU 应答 `0x2003`

### 6.3 基础命令

| 命令码 | 名称 | 方向 | 说明 |
|--------|------|------|------|
| `0x2001` | MCU通用命令 | MCU → DVR | 单片机通用命令 |
| `0x2002` | MCU心跳包 | MCU → DVR | 单片机心跳应答 |
| `0x2003` | MCU版本查询响应 | MCU → DVR | 单片机应答版本信息 |
| `0xA001` | DVR通用命令 | DVR → MCU | DVR 通用命令 |
| `0xA002` | DVR心跳包 | DVR → MCU | DVR 主动发送心跳 |
| `0xA003` | DVR版本查询命令 | DVR → MCU | DVR 主动查询单片机版本 |

> **注**：DVR 侧命令（`0xAxxx`）由单片机解析并查表分发；MCU 侧命令（`0x2xxx`）由单片机发送或应答。

## 7. 示例：DVR 查询 MCU 版本信息

### 7.1 请求帧（DVR → MCU）

**命令**: `0xA003`（DVR版本查询命令）

#### 未转义帧

```
┌──────┬──────────┬──────────┬──────┬────────────┬──────┐
│ 0x7E │ 流水号   │ 命令     │ 无   │ CRC(2字节) │ 0x7E │
└──────┴──────────┴──────────┴──────┴────────────┴──────┘
```

**完整示例**（假设流水号 = 0x0001，CRC = 0xABCD）：

```
未转义：0x7E 0x00 0x01 0xA0 0x03 0xAB 0xCD 0x7E
```

#### 转义后帧

```
转义后：0x7E 0x00 0x01 0x00 0x01 0xAB 0xCD 0x7E
```

> **注**：此示例中无需转义（无 `0x7E` 或 `0x7D` 字节）

### 7.2 响应帧（MCU → DVR）

**命令**: `0x2003`（MCU版本查询响应）

**数据格式**:

| 偏移 | 长度 | 字段 | 说明 |
|------|------|------|------|
| 0 | 40 | sw_version | 软件版本ASCII码，不满40字节时自动补'\0' |
| 40 | 40 | hw_version | 硬件版本ASCII码，不满40字节时自动补'\0' |

#### 未转义帧

```
┌──────┬──────────┬──────────┬────────────────────────────────────┬────────────┬──────┐
│ 0x7E │ 流水号   │ 命令     │ sw_version(40B) + hw_version(40B) │ CRC(2字节) │ 0x7E │
└──────┴──────────┴──────────┴────────────────────────────────────┴────────────┴──────┘
```

**完整示例**（流水号 = 0x0001，CRC = 0x1234）：

```
未转义：0x7E 0x00 0x01 0x20 0x03 [80字节版本数据] 0x12 0x34 0x7E
```

### 7.3 完整交互示例

**场景**：DVR 查询 MCU 版本信息，MCU 回复软件版本 V1.0.260608.01，硬件版本 OC810-M-V1.0

#### 步骤 1：DVR 发送版本查询

```
DVR → MCU：0x7E 0x00 0x01 0xA0 0x03 0xAB 0xCD 0x7E
```

#### 步骤 2：MCU 解析并回复

```
MCU → DVR：0x7E 0x00 0x01 0x20 0x03 [80字节版本数据] 0x12 0x34 0x7E
```

#### 步骤 3：MCU 解析流程

- 收到 DVR 命令 `0xA003`，查 `s_dvr_rx_cmd_table` 分发到 `my_dvr_cmd_handler_version_query`
- 使用相同流水号 `0x0001`，组装应答帧（命令 `0x2003`）
- 填充 sw_version（40字节）+ hw_version（40字节）
- 通过 `my_dvr_cmd_send_response()` 发送应答

## 8. 软件实现建议

### 8.1 发送流程

```c
1. 封装消息（流水号 + 命令 + 数据）
2. 计算 CRC16 校验码
3. 填充 CRC 到消息末尾
4. 执行转义处理
5. 添加首尾标识位 0x7E
6. 通过 UART 发送
```

### 8.2 接收流程

```c
1. 从 UART 接收数据
2. 检测起始标识位 0x7E
3. 执行转义还原
4. 检测结束标识位 0x7E
5. 提取流水号、命令、数据、CRC
6. 验证 CRC 校验码
7. 解析消息内容
8. 根据命令查表分发到对应处理函数
```

### 8.3 流水号管理

- 流水号从 `0x0000` 开始累加
- 每发送一条消息，流水号 +1
- 流水号溢出后（`0xFFFF` → `0x0000`）自动回绕
- 响应消息使用与请求消息相同的流水号

### 8.4 协议栈 API 设计

本项目的单片机端采用三层解耦架构：

1. **协议解析层**（`my_dvr_parse`）：纯粹组帧，不关心内存策略
2. **命令分发层**（`my_dvr_cmd`）：主动请求 / 被动响应 / 命令查表分发
3. **主任务层**（`my_dvr`）：UART 收发、RingBuffer 管理、电源控制、消息调度

#### 8.4.1 主动发送请求（公共 API）

```c
/**
 * @brief   主动发送请求帧（单片机 → 视频模块）
 * @param   cmd          请求命令码
 * @param   payload      负载数据（可为NULL）
 * @param   payload_len  负载长度
 * @return  none
 * @note    流水号由协议层自动递增
 *          内部统一内存策略（小数据静态缓冲，大数据动态分配）
 */
void my_dvr_cmd_send_request(uint16_t cmd,
                                 const uint8_t *payload,
                                 uint16_t payload_len);
```

**调用示例**：
```c
// 主动查询版本（无 payload）
my_dvr_cmd_send_request(0x0001, NULL, 0);

// 主动发送配置数据（带 payload）
uint8_t config[] = {0x01, 0x02, 0x03};
my_dvr_cmd_send_request(0x0010, config, sizeof(config));
```

#### 8.4.2 被动响应（公共 API）

```c
/**
 * @brief   组装并发送响应帧（MCU → DVR）
 * @param   seq          流水号（必须与请求一致）
 * @param   cmd          响应命令码（MCU 侧命令，如 0x2003）
 * @param   payload      负载数据（可为NULL）
 * @param   payload_len  负载长度
 * @return  none
 * @note    流水号由调用方指定，不自动递增
 *          内部统一内存策略（与主动请求复用）
 */
void my_dvr_cmd_send_response(uint16_t seq, uint16_t cmd,
                              const uint8_t *payload, uint16_t payload_len);
```

#### 8.4.3 命令分发（公共 API）

```c
/**
 * @brief   命令分发入口
 * @param   frame  解析后的协议帧
 * @return  none
 * @note    根据 frame->cmd 查静态表分发到具体 handler
 *          未定义的命令将记录警告日志
 */
void my_dvr_cmd_dispatch(const dvr_frame_t *frame);
```

## 9. 错误处理

### 9.1 CRC 校验失败

- 丢弃该帧，不回复
- 记录错误日志（如启用）

### 9.2 超时处理

- **仅针对需要回复的消息**（如请求-响应类命令），不需要回复的消息无需超时检测
- 发送请求后，若 **500ms** 内未收到响应，判定为超时
- 超时后可重试（最多 3 次）
- 3 次超时后上报错误

### 9.3 帧格式错误

- 未检测到起始标识位：等待下一个 `0x7E`
- 转义序列错误：丢弃该帧
- 数据长度超限（≥1024 字节）：丢弃该帧

## 10. 附录

### 10.1 CRC16-CCITT 参考实现

```c
/**
 * @brief   CRC16-CCITT 计算
 * @param   data  数据指针
 * @param   len   数据长度
 * @return  CRC16 校验值
 */
uint16_t crc16_ccitt(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;

    for (uint16_t i = 0; i < len; i++)
    {
        crc ^= (uint16_t)data[i] << 8;

        for (uint8_t j = 0; j < 8; j++)
        {
            if (crc & 0x8000)
            {
                crc = (crc << 1) ^ 0x1021;
            }
            else
            {
                crc = crc << 1;
            }
        }
    }

    return crc;
}
```

### 10.2 转义处理参考实现

```c
/**
 * @brief   消息转义
 * @param   src  原始数据
 * @param   src_len  原始数据长度
 * @param   dst  转义后缓冲区
 * @return  转义后数据长度
 */
uint16_t protocol_escape(const uint8_t *src, uint16_t src_len, uint8_t *dst)
{
    uint16_t dst_len = 0;

    for (uint16_t i = 0; i < src_len; i++)
    {
        if (src[i] == 0x7E)
        {
            dst[dst_len++] = 0x7D;
            dst[dst_len++] = 0x02;
        }
        else if (src[i] == 0x7D)
        {
            dst[dst_len++] = 0x7D;
            dst[dst_len++] = 0x01;
        }
        else
        {
            dst[dst_len++] = src[i];
        }
    }

    return dst_len;
}

/**
 * @brief   转义还原
 * @param   src  转义后数据
 * @param   src_len  转义后数据长度
 * @param   dst  还原后缓冲区
 * @return  还原后数据长度
 */
uint16_t protocol_unescape(const uint8_t *src, uint16_t src_len, uint8_t *dst)
{
    uint16_t dst_len = 0;

    for (uint16_t i = 0; i < src_len; i++)
    {
        if (src[i] == 0x7D && (i + 1) < src_len)
        {
            if (src[i + 1] == 0x02)
            {
                dst[dst_len++] = 0x7E;
                i++;
            }
            else if (src[i + 1] == 0x01)
            {
                dst[dst_len++] = 0x7D;
                i++;
            }
        }
        else
        {
            dst[dst_len++] = src[i];
        }
    }

    return dst_len;
}
```
