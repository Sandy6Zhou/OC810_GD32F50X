## 1. 概述

参数管理系统基于 LittleFS v2.11 文件系统，运行于 GD32F505VGT7 内部 FLASH，提供掉电安全的参数持久化存储。

**核心特性**：
- ID化参数管理（16位ID空间，65536个可用ID）
- 掉电安全（LittleFS copy-on-write 机制）
- 磨损均衡（自动分散写入，延长FLASH寿命）
- CRC32 完整性校验（读取时自动验证）
- 线程安全（FreeRTOS 互斥锁保护）
- 极低资源占用（静态768B RAM，堆88B）

**验证状态**：98项测试全部通过（功能50 + 掉电17 + RAM评估10 + 压力21）

### 2.2 参数ID分配策略

```
┌─────────────────────────────────────────────────────────┐
│  Parameter ID Space (16-bit: 0x0000 ~ 0xFFFF)           │
├─────────────────────────────────────────────────────────┤
│  0x0000          Reserved (系统保留)                     │
│  0x0001 ~ 0x0FFF System Config (系统配置, 4096个)        │
│  0x1000 ~ 0x1FFF Network Config (网络配置, 4096个)       │
│  0x2000 ~ 0x2FFF Device Params (设备参数, 4096个)        │
│  0x3000 ~ 0x3FFF User Settings (用户设置, 4096个)        │
│  0x4000 ~ 0x4FFF Calibration (校准数据, 4096个)          │
│  0x5000 ~ 0xEFFF Reserved for Future (预留, 40960个)     │
│  0xF000 ~ 0xFFFF Reserved (系统保留)                     │
└─────────────────────────────────────────────────────────┘
```

### 2.3 FLASH分区

| 分区 | 大小 | 地址范围 | 用途 |
|------|------|---------|------|
| mcuboot | 48KB | 0x08000000~0x0800BFFF | BootLoader |
| **setting_storage** | **208KB** | **0x0800C000~0x0803FFFF** | **参数存储（LittleFS）** |
| app | 372KB | 0x08040000~0x0809CFFF | 主应用 |
| mcu_secondary | 372KB | 0x0809D000~0x080FAFFF | OTA固件 |
| factory_storage | 20KB | 0x080FB000~0x080FFFFF | 工厂参数 |
| bootconf | 4KB | 0x080FF000~0x080FFFFF | 启动配置 |

> **调试阶段**：setting_storage 临时位于 0x080C7000~0x080FAFFF（Bank1），mcu_secondary 与 setting_storage 重叠（调试不使用OTA），通过 `PARAM_DEBUG_MODE` 宏切换。

## 3. 应用开发者使用指南

### 3.1 快速开始

**Step 1：包含头文件**

```c
#include "param_manager.h"
#include "param_config.h"
```

**Step 2：系统初始化时调用**

```c
/* 在系统初始化任务中（如 init_task） */
int ret = param_manager_init();
if (ret != PARAM_OK) {
    MY_LOG_E("参数系统初始化失败: %d", ret);
    // 处理错误...
}
```

**Step 3：读写参数**

```c
/* 写入一个 uint32 参数 */
uint32_t volume = 75;
param_write(0x0001, &volume, sizeof(volume));

/* 读取参数 */
uint32_t read_val = 0;
int ret = param_read(0x0001, &read_val, sizeof(read_val));
if (ret == sizeof(uint32_t)) {
    MY_LOG_I("volume = %d", read_val);  // 输出: volume = 75
}
```

### 3.2 API参考

#### 核心API

| 函数 | 返回值 | 说明 |
|------|--------|------|
| `param_manager_init()` | PARAM_OK / 错误码 | 初始化（幂等调用安全，首次自动格式化） |
| `param_manager_deinit()` | PARAM_OK / 错误码 | 反初始化（释放资源） |
| `param_write(id, buf, len)` | PARAM_OK / 错误码 | 写入参数（自动CRC32） |
| `param_read(id, buf, len)` | 实际字节数 / 错误码 | 读取参数（自动CRC校验） |
| `param_delete(id)` | PARAM_OK / 错误码 | 删除参数 |
| `param_exists(id)` | 1存在 / 0不存在 / <0错误 | 检查参数是否存在 |
| `param_get_size(id)` | 字节数 / 错误码 | 获取参数数据大小 |
| `param_clear_all()` | PARAM_OK / 错误码 | 清空所有参数 |
| `param_verify_integrity()` | PARAM_OK / 错误码 | 验证所有参数完整性 |

| PARAM_ERR_CRC | -3 | CRC校验失败 |
| PARAM_ERR_MAGIC | -4 | 魔数错误 |

### 3.3 使用示例

#### 示例1：保存设备配置（结构体）

```c
/* 定义配置结构体 */
typedef struct {
    uint8_t  work_mode;       // 0: 正常, 1: 低功耗
    uint8_t  log_level;       // 0: ERROR, 1: WARN, 2: INFO, 3: DEBUG
    uint16_t report_interval; // 上报间隔（秒）
    uint32_t server_port;     // 服务器端口
} device_config_t;

/* 分配参数ID: 0x2001 = 设备参数类别, 编号001 */
#define PARAM_ID_DEV_CONFIG     0x2001

/* 保存配置 */
void save_device_config(const device_config_t *cfg)
{
    int ret = param_write(PARAM_ID_DEV_CONFIG, cfg, sizeof(device_config_t));
    if (ret != PARAM_OK) {
        MY_LOG_E("保存设备配置失败: %d", ret);
    }
}

/* 加载配置（带默认值回退） */
device_config_t load_device_config(void)
{
    device_config_t cfg;
    int ret = param_read(PARAM_ID_DEV_CONFIG, &cfg, sizeof(cfg));
    if (ret != sizeof(device_config_t)) {
        /* 首次使用，使用默认值 */
        cfg.work_mode = 0;
        cfg.log_level = 2;
        cfg.report_interval = 60;
        cfg.server_port = 8800;
        MY_LOG_I("使用默认设备配置");
    }
    return cfg;
}
```

#### 示例8：多任务安全访问

```c
/* 参数系统已内置互斥锁保护，多任务可直接调用，无需额外加锁 */

/* 任务A：定时保存GPS位置 */
void gps_task(void *pvParameters)
{
    while (1) {
        gps_position_t pos = get_current_position();
        param_write(0x2010, &pos, sizeof(pos));  // 线程安全
        vTaskDelay(pdMS_TO_TICKS(10000));
    }
}

/* 任务B：响应用户查询 */
void user_query_task(void *pvParameters)
{
    while (1) {
        gps_position_t pos;
        if (param_read(0x2010, &pos, sizeof(pos)) == sizeof(pos)) {  // 线程安全
            send_to_user(&pos);
        }
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```

### 3.4 注意事项

1. **初始化顺序**：`param_manager_init()` 必须在 FreeRTOS 调度器启动后调用（内部使用互斥锁和堆分配）
2. **数据大小限制**：单个参数数据不超过 4084 字节（4096 - 12字节头部）
3. **返回值检查**：`param_read()` 返回实际字节数，应检查是否等于预期大小
4. **掉电安全**：`param_write()` 内部已调用 `lfs_file_sync()`，数据立即落盘
5. **多任务访问**：无需额外加锁，系统内置 `LFS_THREADSAFE` 互斥保护
6. **参数ID规划**：建议各部门/模块按ID范围分配，避免冲突

## 4. 数据格式

### 4.1 参数文件结构

每个参数以独立文件存储，格式如下：

```c
typedef struct {
    uint16_t    magic;      // 固定 0x504D ("PM")
    uint16_t    version;    // 当前版本: 1
    uint16_t    param_id;   // 参数ID
    uint16_t    data_len;   // 数据字节数
    uint32_t    crc32;      // 数据的CRC32校验
    uint8_t     data[];     // 实际参数数据（可变长）
} param_header_t;           // 总头部: 12字节
```

### 4.2 文件命名规则

```
/params/{category}_{id_4hex}.dat
```

| 类别 | 前缀 | ID范围 | 示例文件 |
|------|------|--------|---------|
| 系统配置 | sys | 0x0001~0x0FFF | /params/sys_0001.dat |
| 网络配置 | net | 0x1000~0x1FFF | /params/net_1001.dat |
| 设备参数 | dev | 0x2000~0x2FFF | /params/dev_2001.dat |
| 用户设置 | usr | 0x3000~0x3FFF | /params/usr_3001.dat |
| 校准数据 | cal | 0x4000~0x4FFF | /params/cal_4001.dat |

## 8. FOTA集成

**关键设计**：setting_storage 与 FOTA 完全隔离。app 与 mcu_secondary 等大（372KB）互为OTA镜像。

```
FOTA更新：mcuboot / app / mcu_secondary / bootconf
FOTA不碰：setting_storage / factory_storage
```

- 固件升级不影响用户参数
- OTA失败后参数仍然完整
- 支持独立升级固件
